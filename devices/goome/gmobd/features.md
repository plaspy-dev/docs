# Goome - GMOBD Features

This page provides a public feature overview for the Goome GMOBD GPS tracker and explains how its capabilities map to Plaspy for vehicle monitoring and fleet oversight. It focuses on practical, non-sensitive information about what the GMOBD is designed to do and how those functions are useful when the device is used with the Plaspy tracking platform.

Exact feature availability and behavior can vary by firmware version, hardware revision, vehicle installation, and the manufacturer's implementation. Use this page as a high-level guide and consult the manufacturer for device specific details and the latest user documentation.

## Feature Overview

The Goome GMOBD is an OBD2 form factor tracker with integrated GSM and BDS/GPS positioning. It is intended to simplify vehicle installation while providing a set of security, tracking, and playback features suitable for car rental, small fleets, and dispatching scenarios.

- Plug-and-play OBD2 compatibility with standard 16-pin OBD interfaces for quick installation in compatible vehicles
- Real-time vehicle location reporting for live monitoring and route awareness
- User-defined geo-fencing with entry and exit alerts to track boundary events
- Trace playback to review historical routes and trip history
- Power-off detection and alerts plus a backup battery to continue reporting if main power is removed
- Built-in vibration and acceleration sensing to support anti-theft and movement alerts

## Core Features of Goome - GMOBD

- OBD2 interface compatibility for 16-pin OBD equipped vehicles
- Integrated GSM and BDS/GPS location modules for positioning and cellular reporting
- Real-time tracking to view current vehicle location on a map
- User-defined geo-fencing for virtual boundary alerts
- Trace playback to review past routes and trips
- Power-off alarm that notifies when the device is disconnected from vehicle power
- Backup battery to maintain operation and reporting during power loss
- Vibration alarm and built-in acceleration sensor for movement and security detection

## How These Features Work with Plaspy

Plaspy receives and normalizes position and event data from compatible trackers like the GMOBD so teams can monitor vehicles, review history, and respond to alerts from a single platform. When used with Plaspy, the GMOBD's signals become actionable items in a fleet monitoring workflow.

- Live vehicle positions displayed on Plaspy maps for operational visibility
- Historical route playback in Plaspy using the device trace data
- Geo-fence events presented as alerts or notifications inside Plaspy
- Power-off and disconnection events visible as device status or alerts for rapid follow up
- Movement and vibration alerts surfaced as security events to support anti-theft workflows
- Device compatibility is handled by Plaspy so GMOBD reports are translated into standard platform events

## Typical Use Cases

- Car rental fleets needing simple plug-in tracking and event alerts
- Small fleet operators who want real-time location and route playback
- Dispatching services that require live vehicle visibility and geo-fence monitoring
- Anti-theft monitoring and movement detection for parked vehicles
- Situations where continued tracking after power loss is important thanks to backup battery support

## Feature Availability Notes

- Feature availability and exact behavior depend on device firmware version and manufacturer settings
- Some vehicle models or OBD2 implementations may provide different power or data characteristics; compatibility is generally with standard 16-pin OBD interfaces
- Backup battery life, alarm sensitivity, and remote functions can vary by hardware revision and regional device variants
- Manufacturer configuration and installation practices can affect which features are active after device setup
- For any critical deployment, confirm supported capabilities against the device documentation and firmware notes

Using the Goome GMOBD with Plaspy brings device-level tracking and event reporting into a centralized platform for monitoring, analysis, and operational response.
