# Suntech - SNT 100 Features

This page provides a public feature overview for the Suntech SNT 100 data terminal and how its capabilities are used with the Plaspy platform. It focuses on user facing functions such as two way messaging, geofence monitoring, remote engine lock and driver behavior analysis, and explains how those capabilities map to visibility and operations inside Plaspy.

Exact feature availability and behavior can vary by device firmware, hardware revision, installation method, and manufacturer implementation. Use this page for general feature context and operational guidance, and consult the manufacturer and installation documentation for device specific details and the current firmware feature set.

## Feature Overview

The SNT 100 is a vehicle data terminal intended to improve communication and monitoring between drivers and a central monitoring station when paired with compatible tracking equipment. Its features emphasize real time communication, location based alerts, and insights into driving performance.

- Two way messaging for direct communication between driver and monitoring station
- Remote engine lock and unlock capability to enhance vehicle security and control
- Geofence monitoring to trigger alerts when a vehicle enters or exits a defined area
- Driver behavior analysis including monitoring of speed acceleration and braking patterns
- Designed to operate alongside Suntech ST300R and ST300H tracking equipment for integrated tracking workflows

## Core Features of Suntech - SNT 100

- Two way messaging that enables text communication between driver and monitoring station
- Remote engine lock and unlock functionality to support security and immobilization workflows
- Geofence creation and monitoring for boundary alerts and route compliance checks
- Driver behavior analysis with reporting on speed acceleration and braking trends
- Integration compatibility with Suntech ST300R and ST300H tracking units
- Centralized communication between driver interface and monitoring station for operational coordination

## How These Features Work with Plaspy

When an SNT 100 is used with Plaspy, its messages and events feed into Plaspy for visibility and operational use. Plaspy receives device reports and presents messaging, alerts, and behavior insights alongside location data so teams can monitor and respond from a single interface.

- Messaging appears in the monitoring station view so dispatch and drivers can exchange instructions
- Remote engine lock commands can be issued from Plaspy and routed to the device when supported by the installed hardware
- Geofence events are displayed on the Plaspy map and can trigger alerts or workflows for dispatch and compliance
- Driver behavior events and summaries are available in Plaspy reporting for coaching and safety analysis
- Plaspy automatically detects the device protocol and accepts tracker reports to integrate device events into the platform
- Devices are commonly configured to report to the Plaspy server domain and use the shared platform port so they appear as managed assets in Plaspy

## Typical Use Cases

- Fleet dispatch communication using two way messaging to coordinate pickups drop offs and route changes
- Security and theft prevention workflows using remote engine lock where permitted and supported
- Route compliance and customer service using geofence alerts for arrivals and departures
- Safety and coaching programs using driver behavior analysis to identify risky driving patterns
- Combined tracking setups where SNT 100 is deployed alongside ST300 series hardware for full tracking and terminal functionality

## Feature Availability Notes

- Features and their exact behavior depend on installed firmware version and device hardware revision
- Remote engine lock functionality typically requires compatible wiring and supporting tracking equipment such as ST300R or ST300H
- Geofence definitions and driver behavior calculations may differ by manufacturer implementation and firmware settings
- Regional variants or installation choices can affect which features are enabled or supported
- Always verify the feature set on the specific device unit and firmware prior to deployment
